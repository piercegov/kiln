# AGENTS.md

This game runs on **Kiln**: a fixed-step loop, a Koota ECS, and a Three.js render bridge. You add a
feature by writing small files and one line in `src/main.ts`, then check it headlessly. The top of
this file is the Kiln guide; the bottom ("This game") is generated by `kiln docs` from the code and
its JSDoc. Re-run `kiln docs` after changing exports or the schedule.

## The loop

```bash
kiln describe            # traits, systems in run order (reads/writes/after), resources, events
kiln test                # bun test over scenarios/ (headless, deterministic)
kiln run --steps 600 --snapshot Transform,Health --resources Score   # JSON world after N steps
kiln check               # determinism lint (Math.random, Date.now, performance.now)
kiln shot --steps 120 out.png        # one rendered frame from headless Chromium, when you need eyes
kiln docs                # regenerate this file
kiln add <plugin>        # vendor a community plugin into src/plugins/ (kiln add --list)
```

Every command takes `--json` and prints errors as `error <code>: <message>`. Messages name the fix.
Work in this order: write or change files → `kiln describe` (schedule errors show here) →
scenario test → `kiln test` → `kiln shot` only if the change is visual.

## Files

```
kiln.config.ts           fixedHz, seed, mode ('3d' | '2d'), hotReload ('keep' | 'snapshot' | false)
src/main.ts              default-exports () => createApp(config)...: the whole schedule
src/traits/x-y.ts        one trait per file; file name = export name in kebab case (XY)
src/systems/x-y.ts       one system per file
src/prefabs/x-y.ts       spawn recipes
src/resources/x-y.ts     singletons
src/events/x-y.ts        event types
src/plugins/<name>/      vendored community plugins (yours to read and edit)
scenarios/*.test.ts      headless tests
public/                  assets, loaded by path ('models/ship.glb' → public/models/ship.glb)
```

Every export gets a one-line JSDoc (`/** ... */`): it is the documentation, and `kiln docs` copies it
here. Import everything from `'kiln'` (physics from `'kiln/physics'`, tests from `'kiln/test'`).

## Core API

```ts
import { trait, relation, Not, Or, Changed, Added, Removed, Mut, system, chain, resource, event,
  prefab, plugin, createApp, CorePlugins, Startup, InputPhase, Fixed, Update, Late, Render,
  Transform, ChildOf, Rng, Input, Camera, Scene, MeshRef, SharedMesh, Instanced, defineInstanced,
  Assets, Model, setYaw, setEuler, distSq, vec3, origin, type Entity } from 'kiln'
```

| Helper | Use |
|---|---|
| `trait({ x: 0 })` | Struct-of-arrays data (numbers, strings, booleans). Fast; rows are live views. |
| `trait(() => obj)` | One object per entity (Three.js objects, arrays, maps). |
| `trait()` | Tag, no data. |
| `relation({ exclusive?, autoDestroy? })` | Koota relation: `ChildOf(parent)`, `Targets(e)`. |
| `system([Mut(A), B, Tag], ([a, b], ctx) => …)` | Runs once per matching entity. Tags and filters give no row entry. |
| `system({ q1: [...], q2: [...] }, ({ q1, q2 }, ctx) => …)` | Runs once per step with views: `.first()`, `.forEach(e)`, `.each(([row], e))`, `.length`. |
| `system((ctx) => …)` | Runs once per step. |
| `chain(A, B, C)` / `A.after(B)` / `A.before(B)` | Order inside a phase. File order never matters. |
| `resource({ value: 0 })` | Singleton. `res.get(R)` reads, `res.mut(R)` writes. |
| `event<{ a: Entity }>()` | `events.emit(E, data)`, `events.read(E)` (each reader sees each event once). |
| `prefab((p: P) => [Transform({...}), …])` | Named spawn recipe: `commands.spawn(Enemy, { at })`. |
| `plugin((app) => { app.init(…).add(…) })` | Bundle of resources, events and systems. Can be async. |

**The context** (`ctx`, second argument of every system):

| Field | |
|---|---|
| `time` | `step` (fixed dt), `dt` (this phase's dt), `elapsed` (simulated seconds), `frame`, `tick`, `alpha` |
| `res` | `res.get(Score)` read-only, `res.mut(Score)` writable |
| `commands` | `spawn(Prefab, params)` / `spawn(...traits)`, `despawn(e)`, `add(e, ...traits)`, `remove(e, ...traits)`; applied at the end of the phase |
| `events` | `emit(E, payload)`, `read(E)` |
| `world` | Koota world for ad-hoc reads (`world.query(...)`); read-only in dev |
| `entity` | The current entity (per-entity form only) |

**Access is in the types.** `Mut(T)` is the write set; every other trait in the query is read-only, so
writing it is a compile error (and a dev error naming the fix). Writes elsewhere: `entity.set(T, {...})`
only with `Mut(T)` in one of the system's queries; never mutate the object `entity.get(T)` returns
(it's a copy for struct traits). Structural changes (spawn, despawn, add, remove) always go through
`commands`.

## Phases (per frame)

1. `Startup`: once before the first frame. Spawn the level, start asset loads.
2. `InputPhase`: polls devices into the `Input` resource (built in; rarely used by games).
3. `Fixed`: 0..N times per frame at `fixedHz` (default 60). Gameplay, physics, AI. Use `time.step`.
4. `Update`: once per frame, variable `time.dt`. Cameras, UI, cosmetic animation.
5. `Late`: end of frame cleanup.
6. `Render`: copies Transform to Three.js (interpolated by `alpha`) and draws. Skipped headless.

Commands apply at the end of each phase run, so a spawn is visible to systems in the next phase run.
Events live for two runs of the phase that emitted them. Startup runs before the first step.

## Rules the schedule enforces at startup

- Two systems in one phase writing the same trait (`Mut(T)`) need an order: put them in `chain()` or
  add `.after()`. The error says which two.
- `.after(X)` needs X in the same phase. Cycles are errors.
- Determinism: randomness only from `res.mut(Rng)` (`float(min,max)`, `int(min,max)`, `chance(p)`,
  `pick(arr)`, `shuffle(arr)`); time only from `ctx.time`. `kiln check` flags the rest. Same seed +
  same input script = same world.

## Rendering and Three.js

- The ECS is the truth; Three.js is a view. Gameplay writes `Transform` (`x y z`, quaternion
  `qx qy qz qw`, scale `sx sy sz`; helpers `setYaw(t, a)`, `setEuler(t, x, y, z)`, `setAngle2D`).
- `MeshRef(object3d)`: adding it puts the object in the scene; despawning removes it and disposes
  geometry/materials unless the entity has `SharedMesh`. Systems may touch materials/uniforms through
  `MeshRef`, but positions always come from `Transform`.
- Many copies of one mesh: `defineInstanced('bullet', { geometry, material })` once, then
  `Instanced('bullet')` (+ optional `InstanceColor({ r, g, b })`) on each entity.
- Hierarchy: `ChildOf(parent)`; the child's Transform is local to the parent.
- `res.mut(Camera)` is a plain Three.js camera (perspective in 3D, orthographic in `mode: '2d'`).
  `res.get(Scene)` is the scene for lights and backgrounds. Teleport without interpolation: add `Teleported`.
- 2D mode keeps the same traits; `z` is draw order and only Z rotation is used.
- Renderer: `WebGPURenderer` (WebGL2 fallback), Three.js pinned to 0.186.1. Write custom materials
  with TSL (see the cheat sheet below); don't use `ShaderMaterial`/GLSL.

## Input

`res.get(Input)`: `axis` (`x` right−left, `y` up−down, length ≤ 1), `down('jump')`,
`pressed('jump')` (exactly once per press, also in Fixed), `released(a)`, `value(a)`, `pointer`
(`x, y, ndcX, ndcY, dx, dy, wheel, down`). Actions: `left right up down jump fire alt interact sprint
pause`, mapped to keys, mouse and gamepad by the `ActionMap` resource. Scripted input for tests:

```ts
app.input.script([
  { frame: 1, hold: 'right', frames: 30 },   // frames count from the script call; 1 = next frame
  { frame: 10, tap: 'jump' },
  { frame: 40, press: 'fire' }, { frame: 50, release: 'fire' },
  { frame: 60, axis: { x: 0, y: 1 } },       // null hands the axis back
  { frame: 70, key: 'KeyE' },                // raw key through the action map
])
```

## Assets

`res.get(Assets).load('models/ship.glb')` (or `.gltf()`, `.texture()`, `.json()`) returns a cached
handle at once: check `handle.ready` / `handle.failed` / `handle.value` in systems; never await in a
system. `commands.spawn(Transform, Model(assets.gltf('models/ship.glb')))` gets a `MeshRef` once loaded.
Start loads in `Startup`; scenarios wait for them before the test body runs.

## Physics (`kiln/physics`, Rapier)

```ts
app.use(CorePlugins, PhysicsPlugin)
commands.spawn(Transform({ y: 5 }), RigidBody, Collider({ shape: 'ball', radius: 0.5 }))
commands.spawn(Transform, RigidBody({ type: 'fixed' }), Collider({ hx: 10, hy: 0.5, hz: 10 }))
```

`RigidBody({ type: 'dynamic' | 'kinematic' | 'fixed', lockRotations, ccd, gravityScale, ... })`,
`Collider({ shape: 'box' | 'ball' | 'capsule' | 'cylinder', hx, hy, hz, radius, halfHeight, friction,
restitution, sensor })`, `LinearVelocity` / `AngularVelocity` (written back each step; write
`LinearVelocity` to drive a body), events `CollisionStarted` / `CollisionEnded` (`{ a, b, sensor }`),
`res.mut(Physics).applyImpulse(e, v)`, `.raycast(origin, dir, maxDist?, exclude?)`. The plugin
runs `CreateBodies → PushState → StepPhysics → WriteBackTransforms` in Fixed, so systems that write
`Transform` or `LinearVelocity` for bodies go `.before(CreateBodies)`; systems that react to the new
positions go `.after(WriteBackTransforms)`.

## Testing

```ts
import { expect, scenario } from 'kiln/test'
import { Transform } from 'kiln'
import { Player } from '../src/prefabs/player.ts'

scenario('player walks right', ({ app }) => {      // fresh app from src/main.ts, Startup already run
  const p = app.spawn(Player, { at: { x: 0, y: 0, z: 0 } })
  app.input.script([{ frame: 1, hold: 'right', frames: 60 }])
  app.step(60)                                     // exactly 60 fixed steps, no renderer
  expect(app.get(p, Transform)!.x).toBeCloseTo(6, 3)
  // app.events(E) lists every E emitted during the last step() call.
}, { seed: 3 })
```

App methods for tests and tools: `step(n)`, `spawn(...)`, `despawn(e)`, `get(e, T)`, `set(e, T, {...})`,
`has(e, T)`, `query(...)`, `res(R)` (mutable), `emit(E, data)`, `events(E)`, `snapshot({ traits,
resources, precision })`, `diff(a, b)`, `restore(snap)`, `describe()`. `scenarioApp(options)` builds an
app yourself (dispose it after).

## A complete feature

```ts
// src/traits/health.ts
import { trait } from 'kiln'
/** Hit points; the entity despawns at 0. */
export const Health = trait({ hp: 3 })

// src/events/damaged.ts
import { event, type Entity } from 'kiln'
/** An entity lost health. */
export const Damaged = event<{ entity: Entity; amount: number }>()

// src/systems/despawn-dead.ts
import { system } from 'kiln'
import { Health } from '../traits/health.ts'
/** Despawns entities whose health reached zero. */
export const DespawnDead = system([Health], ([h], { commands, entity }) => {
  if (h.hp <= 0) commands.despawn(entity)
})

// src/main.ts: one line in the schedule
//   .add(Fixed, chain(PlayerMove, Movement, CollectCoins, DespawnDead))
```

## TSL cheat sheet (three 0.186.1)

Verified on 0.186.1 by the vendored `water` plugin (`kiln add water` for a full working example).

```ts
import * as THREE from 'three'
import { MeshStandardNodeMaterial } from 'three/webgpu'      // node materials come from three/webgpu
import { uniform, positionGeometry, sin, mix, smoothstep, normalize, varying,
  transformNormalToView, vec3, vec4, float, texture, uv, Fn } from 'three/tsl'

// Uniforms. Drive time from the deterministic sim clock, not TSL's wall-clock `time`.
const uTime = uniform(0)
const uHeight = uniform(0.3)
const uDeep = uniform(new THREE.Color(0x1b5e8c))
const uCrest = uniform(new THREE.Color(0x9fd8f0))
// in an Update system:  uTime.value = time.elapsed + (time.alpha - 1) * time.step

const mat = new MeshStandardNodeMaterial({ roughness: 0.3 })

// Vertex displacement: read the undisplaced vertex from positionGeometry.
const p = positionGeometry
const h = sin(p.x.mul(0.55).add(uTime.mul(1.1))).mul(uHeight)   // .add .mul .negate, JS numbers ok
mat.positionNode = vec3(p.x, p.y.add(h), p.z)

// Normals for displaced geometry are in view space; varying() computes them per vertex.
const dhdx = sin(p.x.mul(0.55).add(uTime.mul(1.1)).add(Math.PI / 2)).mul(uHeight).mul(0.55)
mat.normalNode = normalize(varying(transformNormalToView(normalize(vec3(dhdx.negate(), 1, 0)))))
// (or: new MeshStandardNodeMaterial({ flatShading: true }) for faceted normals)

// Colour: pass a vertex value to the fragment stage with varying(), blend with mix/smoothstep.
mat.colorNode = mix(uDeep, uCrest, smoothstep(uHeight.negate(), uHeight, varying(h)))

// Textures, tiled UVs, and reusable functions:
const tint = Fn(([c]: [any]) => c.mul(vec4(1, 1, float(0.5), 1)))
// mat.colorNode = tint(texture(myTexture, uv().mul(2)))

commands.spawn(Transform, MeshRef(new THREE.Mesh(new THREE.PlaneGeometry(20, 20, 64, 64).rotateX(-Math.PI / 2), mat)))
```

- Plain `MeshStandardMaterial` / `MeshBasicMaterial` (incl. `vertexColors`, `flatShading`) work unchanged.
- Don't use `ShaderMaterial`, `onBeforeCompile` or GLSL strings; they don't run on WebGPU.
- Building node materials headless (Bun, scenarios) is fine; nothing compiles until render.
- For per-instance data that changes every step, prefer `InstanceColor` (Kiln) or an
  `InstancedBufferAttribute` on the geometry.

## Common errors

| Error | Fix |
|---|---|
| `A and B both take Mut(T) in Fixed with no order` | `chain(A, B)` or `B.after(A)` |
| `X wrote T.f, but its query takes T read-only` | `Mut(T)` in X's query |
| `X called entity.destroy() during Fixed` | `commands.despawn(entity)` |
| `X wrote Score.value through res.get(Score)` | `res.mut(Score)` |
| `X wrote T.f on the copy entity.get() returns` | write through the row, or `entity.set(T, {...})` with `Mut(T)` |
| `app.step() ran while an async plugin is still loading` | `await app.ready()` (scenarios do it) |
| `No trait named "X"` (kiln run) | check `kiln describe`; names come from exports |
